# Stride 匹配序列设计文档

**文档版本**：2.0
**更新日期**：2026-09-12
**适用模块**：`stride/matcher.h`（匹配序列模块）

---

> **输入模型**：Stride 只编译**单个段（segment，不透明二进制）**的模式；按 `/` 等分隔符切分输入由调用方负责。
> 匹配序列只描述“在一个段内如何**按步移动**、在哪些位置**比对哪些比特串**”，供调用方在自己的匹配逻辑中使用。
>
> **单位**：步长的单位是**比特**；位置与偏移以**步**计（比特偏移 = 步 × 步长）；
> 字面量长度与段长以**比特**计（`1 字节 = 8 比特`）。

---

## 一、概述

匹配序列（Match Sequence）是 Stride 匹配阶段的核心数据结构。它将**单个段**的模式编译为一个元组序列，
每个元组描述一个**按步计的移动操作**和在该位置需要比对的**比特串**。

匹配阶段只执行匹配序列，不关心捕获细节，从而实现高性能的序列匹配。

```
单个段的模式
      │  stride_lex()
      ▼
stride_op_t 操作符序列
      │  stride_match_compile()
      ▼
stride_match_op_t 匹配序列（按步移动 + 比特串比对）
```

匹配序列模块不关心操作符从何而来，也不关心段从何而来：它的输入是一段模式的操作符序列，输出是该段的匹配序列。

## 二、核心概念

### 2.1 操作符分类

段模式中的操作符分为三类，各有不同的编译目标：

| 类别 | 操作符 | 作用 | 匹配序列中的处理 |
|------|--------|------|------------------|
| **比对** | `$'比特串'` | 验证字面量 | 产生 `expect`，参与序列区分 |
| **捕获** | `${}`、`${n}`、`${'S'}` | 提取参数 | 仅按步移动，不参与序列区分 |
| **移动** | `$[n]`、`$[>n]`、`$[<n]`、`$[>'S']`、`$[<'S']`、`$[END]` | 调整位置 | 仅按步移动，不参与序列区分 |

**核心原则**：匹配序列只保留匹配所需的信息（步进 + 比特串），捕获操作的参数提取信息被丢弃。

### 2.2 步长与“步”

段是不透明二进制，长度以**比特**给出。引入**步长 `s`** 后，段内位置统一以**步**度量：

| 概念 | 定义 |
|------|------|
| 步长 `s` | 每一步跨越的**比特数**（由 API 指定，`s ≥ 1`） |
| 段长 `Lb` | 段的**比特长度** = `8 × 字节数` |
| 步数 `N` | `N = Lb / s`，要求 `Lb % s == 0` |
| 比特偏移 | `步序号 × s` |

常见步长：位域 `1`、半字节 `4`、字节流 `8`、UTF-16 码元 `16`、8 字节定长记录 `64`。
只要长度能被整除，任意步长都合法——例如 `$'abc'`（24 比特）对步长 `2`、`3`、`4`、`6`、`8`、`12`、`24` 均可。

**匹配序列与步长无关**：产物中所有 `steps` 字段都只记录**步数**，`bit_len` 只记录**比特长度**，
编译期不需要知道 `s`。因此同一份匹配序列可按不同步长执行，只要满足对齐约束。

> 步长在执行期传入 `stride_match_run()`；编译期若已知步长，可提前校验（传 0 表示未知）。

### 2.3 HEAD 与 END

每个段有两个不可变的位置基准，均以**步**为单位：

| 基准 | 定义 | 值 | 性质 |
|------|------|-----|------|
| **HEAD** | 段数据的开始位置 | 0 步 | 编译时已知的符号标志 |
| **END** | 段数据的结束位置 | 运行时确定的总步数 `N` | 运行时已知的符号标志 |

**重要说明**：
- `HEAD` 与 `END` 都是**符号标志**，不是数值，必须显式出现
- `HEAD` 虽然数值为 0，但语义上代表“段首”这一绝对基准
- `END` 在编译时以符号形式保留，运行时替换为 `N = Lb / s`

### 2.4 移动操作的分类

| 类别 | 基准 | 说明 | 示例 |
|------|------|------|------|
| **步进操作** | HEAD、END 或当前游标 | 编译时可计算的固定步进 | `(n, expect)`、`(HEAD+n, expect)`、`(END−n, expect)` |
| **查找操作** | 当前游标 | 运行时才能确定目标位置 | `("S", expect)`、`("<", "S", expect)` |

## 三、元组定义

### 3.1 元组类型

| 类别 | 操作符来源 | 基础元组 | 语义 |
|------|-----------|---------|------|
| **步进** | `${n}`, `$[>n]` | `(n, NULL)` | 向段尾移动 `n` 步 |
| **步进** | `$[<n]` | `(−n, NULL)` | 向段首移动 `n` 步 |
| **步进** | `$[n]` | `(HEAD+n, NULL)` | 移动到第 `n` 步 |
| **步进** | `$[END]`, `${}` | `(END, NULL)` | 移动到段尾（第 `N` 步） |
| **步进** | `$[END−n]` | `(END−n, NULL)` | 移动到第 `N−n` 步 |
| **查找** | `${'S'}`, `$[>'S']` | `("S", NULL)` | 向段尾查找比特串 `S` |
| **查找** | `$[<'S']` | `("<", "S", NULL)` | 向段首查找比特串 `S` |
| **比对** | `$'比特串'` | `(0, "比特串")` | 移动 0 步后比对字面量 |

`S` 是**任意长度的比特串**（可为多比特，如 UTF-8 中文 = 24 比特）。查找只在**步对齐**位置进行。

### 3.2 元组字段

```c
/* stride/matcher.h */

typedef struct {
    const void *data;    /* 数据（拥有副本） */
    size_t      bit_len; /* 比特长度 */
} stride_blob_t;

typedef struct {
    stride_match_type_t type;
    size_t              steps;     /* 非负步数：相对步数 / END 偏移 / HEAD 位置 */
    stride_blob_t       delimiter; /* FIND_* 的查找目标；其他类型为空 */
    stride_blob_t       expect;    /* 在该处要比对的字面量；可为空 */
} stride_match_op_t;
```

**steps 字段语义**：

| type | steps 含义 |
|------|-----------|
| `STRIDE_MT_STEP_FWD` | 向段尾移动的步数 |
| `STRIDE_MT_STEP_BACK` | 向段首移动的步数 |
| `STRIDE_MT_ABS_HEAD` | 目标步位置 = `HEAD + steps` |
| `STRIDE_MT_ABS_END` | 目标步位置 = `END − steps`（0 表示段尾） |
| `STRIDE_MT_FIND_FWD` | 未使用（查找目标在 `delimiter`） |
| `STRIDE_MT_FIND_REV` | 未使用（查找目标在 `delimiter`） |

**表示约定**：`steps` 一律存储**非负幅度**，移动方向由 `type` 表达。
例如 `$[<3]` 产生 `STEP_BACK`、`steps = 3`；`$[END-4]` 产生 `ABS_END`、`steps = 4`。

**长度约定**：`delimiter.bit_len`、`expect.bit_len` 均为**比特数**；
比对与查找消耗的步数 = `bit_len / 步长`（要求整除）。

**所有权说明**：`delimiter` 与 `expect` 由匹配序列模块拥有，`stride_match_compile()`
复制其内容，调用方通过 `stride_match_free()` 释放。

### 3.3 元组示例

| 操作符 | 基础元组 |
|--------|---------|
| `$'user'` | `(0, "user")`（32 比特） |
| `${2}` | `(2, NULL)` |
| `$[>3]` | `(3, NULL)` |
| `$[<2]` | `(−2, NULL)` |
| `${'='}` | `("=", NULL)` |
| `$[>'=']` | `("=", NULL)` |
| `$[<'=']` | `("<", "=", NULL)` |
| `$[5]` | `(HEAD+5, NULL)` |
| `$[END]` | `(END, NULL)` |
| `${}` | `(END, NULL)` |
| `$[END-4]` | `(END−4, NULL)` |
| `${'：'}` | `("：", NULL)`（24 比特） |

## 四、编译规则

### 4.1 步进操作相加

同类型的步进元组按**步数**相加：

| 规则 | 示例 |
|------|------|
| `(n, NULL) + (m, NULL) = (n+m, NULL)` | `(2, NULL) + (3, NULL) = (5, NULL)` |
| `(HEAD+n, NULL) + (m, NULL) = (HEAD+n+m, NULL)` | `(HEAD+2, NULL) + (3, NULL) = (HEAD+5, NULL)` |
| `(END−n, NULL) + (−m, NULL) = (END−n−m, NULL)` | `(END−5, NULL) + (−2, NULL) = (END−7, NULL)` |

**约束**：
- `HEAD` 最终结果必须为 `HEAD + n`，`n ≥ 0`
- `END` 最终结果必须为 `END − n`，`n ≥ 0`
- 不同基准不能相加：`(HEAD+2, NULL) + (END−3, NULL)` 无效

### 4.2 查找操作的行为

查找操作**不可相加**：遇到查找操作时先输出当前 HOLD 的步进元组（如有），查找操作自身成为新的 HOLD。

```
输入：${2}${'a'}${3}

状态机：
  IDLE + (2, NULL) → HOLD(2)
  HOLD + ("a", NULL) → 输出 (2, NULL)，HOLD("a")
  扫描结束 → 输出 ("a", NULL)

输出：[(2, NULL), ("a", NULL)]
```

### 4.3 字面量合并

比对字面量元组 `(0, kw)` 与当前 HOLD 合并后输出：

| 规则 | 示例 |
|------|------|
| `(n, NULL) + (0, kw) = (n, kw)` | `(2, NULL) + (0, "key") = (2, "key")` |
| `("S", NULL) + (0, kw) = ("S", kw)` | `("a", NULL) + (0, "key") = ("a", "key")` |
| `(HEAD+n, NULL) + (0, kw) = (HEAD+n, kw)` | `(HEAD+5, NULL) + (0, "key") = (HEAD+5, "key")` |
| `(END−n, NULL) + (0, kw) = (END−n, kw)` | `(END−4, NULL) + (0, "key") = (END−4, "key")` |

### 4.4 连续字面量

两个 `$'比特串'` 可以直接相邻书写，但**不推荐**：会产生多余的 `(0, kw)` 元组。
建议合并为一条，如 `$'ddaaa'`。

### 4.5 扫描结束处理

扫描结束时若在 HOLD，输出持有元组：

```
输入：${2}${3}
  IDLE + (2, NULL) → HOLD(2)
  HOLD + (3, NULL) → HOLD(5)
  扫描结束 → 输出 (5, NULL)

输出：[(5, NULL)]
```

> 状态转换表、步进相加与字面量合并的完整规则见
> [`Stride 状态机设计文档.md`](Stride%20状态机设计文档.md)。

## 五、编译示例

单位均为步；括号内为「步长 8（1 字节/步）」下的参考换算。

### 5.1 步进相加

```
输入：${1}${1}${1}$'key'
输出：[(3, "key")]      // "key" = 24 比特 = 3 步
```

### 5.2 查找打断

```
输入：${2}${'a'}${3}$'b'
输出：[(2, NULL), ("a", NULL), (3, "b")]
```

### 5.3 绝对定位与步进相加

```
输入：$[5]${2}$'key'
输出：[(HEAD+7, "key")]
```

### 5.4 段尾回退

```
输入：${}$[<4]$'dddd'
输出：[(END−4, "dddd")]
```

### 5.5 版本号解析

```
段模式：$'v'${'.'}$'.'${}
输出：[(0, "v"), (".", "."), (END, NULL)]
```

### 5.6 多比特定界

```
段模式：$'用户'${'：'}$'：'${}
输出：[(0, "用户"), ("：", "："), (END, NULL)]
```

## 六、字面量与序列区分

### 6.1 字面量的作用

匹配字面量（`expect.bit_len > 0`）是区分不同模式序列的**唯一依据**：

- 携带字面量的元组参与调用方的序列区分（例如被登记进调用方自建的索引 / 分派结构）
- 纯移动元组（`expect.bit_len == 0`）不参与区分

### 6.2 唯一性保证

两个不同模式的匹配序列，在**所有携带字面量的元组**上必须不同，否则视为冲突。

元组的类型与参数都参与区分：
- `(3, "key")` 与 `(HEAD+3, "key")` 类型不同
- `("a", NULL)` 与 `("b", NULL)` 查找目标不同
- `(END−4, "key")` 与 `(END−5, "key")` 偏移不同
- `(0, "a")` 与 `(0, "ab")` 比特长度不同

**职责边界**：Stride 只负责为**单个段**产出匹配序列，不建立跨模式的集合，也不做跨模式冲突检测。
同类匹配序列登记进同一索引时，调用方必须保证步长一致，否则 `steps` 的比特含义不同。

## 七、数据结构定义

```c
/* stride/matcher.h */

typedef enum {
    STRIDE_MT_STEP_FWD = 0, /* 步进向段尾：(n, expect) */
    STRIDE_MT_STEP_BACK,    /* 步进向段首：(−n, expect) */
    STRIDE_MT_ABS_HEAD,     /* 绝对步位置（基于 HEAD）：(HEAD+n, expect) */
    STRIDE_MT_ABS_END,      /* 绝对步位置（基于 END）：(END−n, expect) */
    STRIDE_MT_FIND_FWD,     /* 向段尾查找比特串：("S", expect) */
    STRIDE_MT_FIND_REV      /* 向段首查找比特串：("<", "S", expect) */
} stride_match_type_t;

typedef struct {
    const void *data;
    size_t      bit_len;
} stride_blob_t;

typedef struct {
    stride_match_type_t type;
    size_t              steps;     /* 非负步数 */
    stride_blob_t       delimiter; /* 查找目标（比特串） */
    stride_blob_t       expect;    /* 比对字面量（比特串） */
} stride_match_op_t;
```

**对齐约束**：执行时要求段比特长度 `Lb % 步长 == 0`，且每个非空字面量 `bit_len % 步长 == 0`；
违反时报 `STRIDE_E_ALIGN`。

## 九、设计原则总结

1. **段是二进制**：匹配序列不解释段的内容与编码
2. **游标以步计**：字节/比特偏移 = 步 × 步长
3. **比特为单位**：步长是每步比特数；长度以比特计
4. **产物与步长无关**：编译期无须知道步长，执行期校验对齐
5. **HEAD 与 END 是符号标志**：必须显式出现，不可省略
6. **步进与查找分离**：步进可相加，查找不可相加
7. **字面量驱动**：只有字面量参与序列区分
8. **查找打断**：查找操作触发当前 HOLD 输出
9. **字面量合并**：字面量与当前 HOLD 合并后输出
10. **END 约束**：最终结果必须为 `END − n`，`n ≥ 0`
11. **HEAD 约束**：最终结果必须为 `HEAD + n`，`n ≥ 0`
12. **对齐约束**：段长与字面量比特长度必须是步长整数倍
13. **确定性**：匹配序列唯一确定匹配路径
14. **单段编译**：一个匹配序列对应一个段；跨段组织由调用方负责

## 十、编译接口

```c
/* stride/matcher.h */

/**
 * 匹配序列编译：操作符序列 → 匹配序列
 * @param ops           操作符数组（单个段的模式词法分析结果）
 * @param op_count      操作符数量
 * @param stride        编译期步长（比特/步）；0 表示未知（不校验对齐），≥1 表示已知
 * @param out_ops       输出匹配元组数组（调用方通过 stride_match_free 释放）
 * @param out_count     输出元组数量
 * @param out_capacity  输出数组容量
 * @return 0 成功，-1 失败
 */
int stride_match_compile(const stride_op_t *ops, size_t op_count,
                         size_t stride,
                         stride_match_op_t **out_ops,
                         size_t *out_count, size_t *out_capacity);

/**
 * 释放匹配元组数组（含每个元组的 delimiter 与 expect）
 */
void stride_match_free(stride_match_op_t *ops, size_t count);
```

## 十一、匹配接口

编译出匹配序列之后，由匹配器在段上执行它。匹配是纯读取操作，不产生参数、
不修改匹配序列，也不依赖提取序列。

```c
/* stride/matcher.h */

/**
 * 用匹配序列匹配一个段
 * @param ops              匹配元组数组
 * @param count            元组数量
 * @param stride           执行期步长（比特/步，必须 ≥ 1；0 视为 1）
 * @param segment          段数据（不透明二进制）
 * @param segment_bit_len  段比特长度
 * @return 0 匹配成功，-1 不匹配
 */
int stride_match_run(const stride_match_op_t *ops, size_t count, size_t stride,
                     const void *segment, size_t segment_bit_len);

/**
 * 匹配详情（用于诊断 / 自建索引）
 * fail_index <  count：第 fail_index 个元组失败
 * fail_index == count：元组全部执行成功，但游标未落在段尾
 */
typedef struct {
    int    matched;
    size_t fail_index;
    size_t cursor; /* 单位：步 */
} stride_match_detail_t;

int stride_match_run_ex(const stride_match_op_t *ops, size_t count, size_t stride,
                        const void *segment, size_t segment_bit_len,
                        stride_match_detail_t *out);
```

### 11.1 匹配算法

设步长 `s`、段比特长度 `Lb`。先校验 `Lb % s == 0`，再计算 `N = Lb / s`。
维护游标 `pos`（单位：步），初始 0，始终满足 `pos ≤ N`。按顺序处理每个元组：

| 元组类型 | 动作 | 失败条件 |
|---------|------|---------|
| `STEP_FWD` | `pos += steps` | 越过段尾 |
| `STEP_BACK` | `pos -= steps` | 越过段首 |
| `ABS_HEAD` | `pos = steps` | `steps > N` |
| `ABS_END` | `pos = N − steps` | `steps > N` |
| `FIND_FWD` | 从 `pos` 起在**步对齐**位置查找 `delimiter`，命中则 `pos = 命中步` | 未找到 |
| `FIND_REV` | 从 `pos − 1` 步（`pos == 0` 时为 `N − 1` 步）向段首查找，命中则 `pos = 命中步` | 未找到 |

移动完成后，若该元组携带 `expect`，则在 `pos` 处比对比特串：失败即失败，
相等则 `pos += expect.bit_len / s`（字面量被消耗）。

所有元组处理完毕后，还要求 `pos == N`（**段尾对齐**），否则视为不匹配。

**查找的对齐规则**：

```c
/* 正向：候选起始步 k 从 pos 到 N - delim_steps（含），取最小 k */
for (k = pos; k + delim_steps <= N; k++)
    if (bits_eq(seg, k * s, delimiter.data, delimiter.bit_len)) { pos = k; break; }

/* 反向：候选起始步 k 从起点向 0 递减，取最大 k */
for (k = start; ; k--) {
    if (bits_eq(seg, k * s, delimiter.data, delimiter.bit_len)) { pos = k; break; }
    if (k == 0) fail;
}
```

其中 `delim_steps = delimiter.bit_len / s`。查找**不逐比特滑动**，因此不会匹配到某个步的内部。

**比特比较 `bits_eq`**：比较从 `seg` 的第 `bit_off` 比特开始、长度 `bit_len` 的比特串与
`data`。当 `bit_off % 8 == 0` 且 `bit_len % 8 == 0` 时退化为 `memcmp(seg + bit_off/8, data, bit_len/8)`；
否则按比特移位比较（支持非字节对齐的步长，如 4 比特/步）。

> `bits_eq` 不解释内容；UTF-8 的自同步性保证整段多比特序列不会匹配到某字符内部，
> 因此多比特定界在步长 8 下天然按字符对齐。

### 11.2 与提取的一致性

匹配器与提取器对“移动”的解释完全一致：同一个模式经匹配序列匹配与经提取序列提取，
游标轨迹相同。区别只在于：

- 匹配阶段**比对**字面量，提取阶段只跳过字面量步数（不再重复验证）；
- 匹配阶段丢弃捕获边界，提取阶段保留捕获边界并产出参数。

因此调用顺序应为：先 `stride_match_run()` 判定命中，再 `stride_extractor_run()` 提取参数。
两次调用必须使用**相同的步长**。

### 11.3 示例

```
模式：$'v'${'.'}$'.'${}
匹配序列：[(0,"v"), (FIND_FWD ".", "."), (END, NULL)]
步长：8（1 字节/步）

段 "v2.0"（32 比特，N=4）：
  (0,"v")            → 游标 0，字面量 "v" 比对成功，游标 1
  (FIND_FWD ".", ".") → 从 1 找到 '.' 于 2，游标 2；字面量 "." 比对成功，游标 3
  (END, NULL)         → 游标 4
  段尾对齐：4 == 4 → 匹配成功

段 "v2"（16 比特，N=2）：
  (0,"v")            → 游标 1
  (FIND_FWD ".", ".") → 未找到 '.' → 匹配失败
```

```
模式：$[>'：']$[>3]${}
匹配序列：[("：", NULL), (3, NULL), (END, NULL)]
步长：8（1 字节/步）

段 "用户：alice"（UTF-8，112 比特，N=14）：
  ("：", NULL) → 从 0 步对齐查找，命中于第 6 步（"："的起始），游标 6
  (3, NULL)    → 游标 9（跨过 24 比特的"："）
  (END, NULL)  → 游标 14
  段尾对齐：14 == 14 → 匹配成功
```
